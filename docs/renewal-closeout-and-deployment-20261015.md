# 自动续期路线收口与 108 诊断／今日状态部署

## 最终工程结论

截至 2026-10-15，在现有合法输入、纯 Rust 生产与安全边界下，不能把自动 Cookie／后端会话续期、独立新密钥合法签发或无人值守动态签名作为可靠生产能力交付。**停止这条未验证路线的工程推进与交付，不启用候选能力。** 这是基于当前证据的交付决定，不是“技术上永远不可能”的证明。

既有研究证据、离线工具与失败关闭门禁保留，不删除证据，不通过导入浏览器私钥、复用签名或伪装宿主补齐未知项。生产仍只有 Rust 服务，不引入 Node、浏览器、CDP、外部签名服务或 Docker 代理。

### 分项证据与欠缺

- **Cookie／后端会话延寿**：历史 browser／Rust TokenBeat 返回成功，但观察到的八项 HttpOnly Cookie 元数据未改变，Rust 响应 `Set-Cookie=0`；未证明后台 TTL 延长。Cookie 检查只证明当时会话可用，TokenBeat 只按保活处理。缺少可归因、可复现的有效期延长证据及合法续期流程。
- **独立新密钥合法签发**：历史隔离新 P-256 候选未得到与新密钥匹配的 ticket／ts_sign／client_cert；匹配材料数量为 0。官方消费者可以存储不完整材料，`setSignValueAsync=true`、`is_storage=1` 都不能证明签发、密钥绑定或信任。缺少平台合法签发及有效期／账号／会话绑定证明。
- **跨引擎签名一致**：原始锁定 BDMS 的 QuickJS、Node、合成浏览器宿主输出不一致；本机浏览器不同调用入口也不一致。已观察 VM704／705 的真实内部栈读取，但单向量观察器对照不构成跨引擎等价或账号页宿主等价。缺少合法初始化、实际依赖的完整解释与非伪装的一致性证明。
- **服务端接受**：公共 ECDSA、ECDH／HKDF／HMAC 对照仅证明公开算法互操作。历史单次发送成功依赖固定账号／目标的一次性官方材料，不是独立 Rust 生成签名获接受或自动续期。缺少独立生成、正确绑定的合法请求获服务端接受及稳定生命周期证明。

可追溯来源：`docs/sdk-evidence.md`、`docs/sdk-offline-continuation-20261015.md`、`docs/sdk-acceptance-20261014.md`。本轮没有新增平台探测来填补上述未知项。

生产 `KNOWN_RELEASES` 保持空；本轮 `sdk_audit check` 四项资源校验通过，`activate` 仍以 `no approved known pin; missing adapter` 拒绝。资源哈希匹配、离线样例、存储成功、Cookie 更新及历史单次发送均不作为续期证明。
