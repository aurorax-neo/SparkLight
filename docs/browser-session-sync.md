## 实现

- 现有 `sync_from_browser` 接口接收 Cookie 后，由同一 Rust 客户端确认预期 UID、获取官方 IM 身份、再次确认身份。
- Cookie 与只读 IM 上下文在一个事务中加密保存；更新条件包含原 Cookie 密文、账号 UID 及允许的账号状态。
- 并发替换 Cookie、身份变化、续取失败、停用账号或事务失败均不覆盖原数据。
- 成功同步清除该账号旧发送凭证，不创建发送签名、不延长旧凭证时间、不触发发送/好友发现/全账号任务。
- 返回值明确区分历史上下文就绪与 `send_authorization_status=MISSING`。历史上下文就绪不等于已检查完整历史。

新增 `src/douyin/browser_session.rs`，接入 `client.rs` 和 `accounts.rs`，离线用例位于 `im_identity_tests.rs`。此前尚未部署的 `session_auth.rs` 探索代码保留，未集成发送路径。

## 尚未解决

Cookie 与身份 token 同步不能代替当前消息所需的新发送授权。现有历史成功证据来自一次性浏览器捕获导入；该证据不支持长期自动签发，也不授权重放旧签名。当前尚无经验证的新授权获取适配器，因此未部署本次修改，未进行真实续火验收。

此前“只有登录才能签发”“纯 Rust 客观不可能”“浏览器同步 100% 无风险”等绝对判断没有充分证据，不应作为技术结论。后续需要验证合法新授权来源，再接入目标、身份、完整历史和原子单次消费校验；不能靠删除门禁或创建替代尝试标记推进。
