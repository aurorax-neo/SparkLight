## 后续根因修复与真实验证（2026-10-15 12:12 北京时间）

### 协议与根因

- 官方普通私信 SDK 的 `SESSION_AUTH=1`、空顶层 token 用于会话 Cookie 鉴权；身份安全 token 只在发送前通过 `updateSendMessageHeaders` 合入，历史查询不应依赖先捕获 cmd100 发送报文。
- 原 `WebSessionContext::from_credential` 是唯一本地创建来源，导致没有发送捕获就无法查询历史。新增 `from_session`，仅在官方登录资料确认 UID 后建立 10 分钟、UID/Cookie 绑定且只允许 cmd301/610 的上下文。未延长原上下文或一次性发送授权寿命。
- `15314.1abe9892.js` 的身份 SDK 默认 GET `/passport/safe/get_identity_security_token/`，普通私信使用 scene=web_im、id_token_version=1.2.10、Passport lite=4.2.3。响应 token 与 device_id 必须同时存在；不猜测设备 ID。官方 SDK 的 Ticket Guard 消费者配置仍存在，单账号请求成功不证明其他会话或未来请求不需额外鉴权。
- 只登记该精确 HTTPS GET 接口；不重定向、不自动重试，不执行二次验证。增加 Passport 验证决策头和身份时间错误头停止规则。失败不伪造凭证。

### 实现

- 单条刷新使用 `POST /api/v1/targets/{id}/refresh`，失败恢复仅 GET 当前目标；不再调用账号好友同步、全部目标失效或全列表重载。
- 单条刷新和账号同步按需获取身份 token、同客户端复查 UID，并将 Cookie/上下文同事务加密保存。保存使用原加密 Cookie、UID、ACTIVE 状态作条件，防止覆盖请求期间更换的新会话。
- 当前目标使用单元素 cmd610 获取实际 shortID，再查询 cmd301。其他目标不更新；系统当天成功优先于历史 false，跨北京时间零点结果保持未知。
- 刷新返回凭证状态并更新本地当前账号缓存，不触发整表刷新。
- token/只读上下文不是一次性发送签名，未自动生成或复用发送授权，生产 SDK 审批门禁保持不变。
